# primlib

> [!CAUTION]
> **All the code in this repository was generated by Claude, an AI from Anthropic, and has not been checked by a person.** It may have bugs or not do what it says. Read it before you rely on it, and use it at your own risk.

Parametric primitives for 3D-printed parts: hinges, latches, rails, box edges and corners, print supports. Each primitive's sizes are expressions over named parameters.

- **In FreeCAD** the parameters are spreadsheet aliases: edit a cell, recompute, and the part follows. The objects are plain FreeCAD (spreadsheet, sketch, Part and PartDesign), so saved files open without primlib installed.
- **As a file:** any primitive exports as a `.prim` file ([docs/FORMAT.md](docs/FORMAT.md)) that other programs can build at any values without FreeCAD. [view4d](https://github.com/sawdustandswarf/view4d) reads them.

**Documentation:** every primitive has a generated page with drawings and its parameters: **https://sawdustandswarf.github.io/primlib/** (the same pages are `index.html` and `primlib/primitives/*.html` in this repository). The plan is in [docs/PLAN.md](docs/PLAN.md).

Status: a working hobby library. Parts marked *not yet printed* are untested in the real world, and the deprecated ones are on their way out.

## Using it

Installing is optional. It adds a toolbar and lets `import primlib` work without any setup. Everything also works without installing.

### Without installing

FreeCAD only needs to know where this folder is. In FreeCAD's Python console (View → Panels → Python console), or at the top of a macro:

```python
import sys
sys.path.append("/path/to/primlib")   # this folder
import primlib

doc = App.ActiveDocument
primlib.make("pin", doc, "Pin")
doc.recompute()
```

From a terminal, run a script with `freecadcmd my_script.py`; the script needs the same two `sys.path` lines at the top.

### Installing (optional, once)

Run this in a normal terminal, not in FreeCAD:

```bash
cd primlib
./install.sh
```

It creates one symlink, `~/.local/share/FreeCAD/v1-1/Mod/primlib`, pointing at this folder. Edits here take effect the next time FreeCAD starts, with no reinstall. To uninstall, delete the symlink. After restarting FreeCAD:

- `import primlib` works in the console, in macros and in `freecadcmd` with no `sys.path` line.
- The workbench dropdown has an **primlib** workbench, with one button per primitive, a Documentation button and a Reload button. Click a primitive to add it to the active document. Its parameters go into the `Params` sheet, or into a spreadsheet you selected in the tree first.
- **Reload** loads the library again from disk, so after editing a primitive or the core you don't need to restart FreeCAD. The next button click, and any `primlib.make(...)` in the console, use the new code. Parts already in a document are left as they are. A newly added primitive file works with `primlib.make` straight after Reload, but it only gets a toolbar button after a restart.

### The parameter sheet

Every part's parameters go into one document-wide spreadsheet, `Params`, which is created on first use. Each part is appended at the bottom as its own section: a bold title row (`Pin: Retained pin`), then one aliased row per parameter, prefixed with the part's name so two pins don't clash:

```
alias               value    note
Pin: Retained pin
Pin_height          10       overall height, end face to end face
Pin_diam            6        shaft diameter
...

Sleeve: Sleeve
Sleeve_height       10       sleeve height, one pin segment
...
```

Edit a value and recompute; only that part changes. If a part fails its checks, the rows it added are removed again.

### Holes and plates

(Deprecated with the old hinge: `pin`, `sleeve`, `sleeve_clearance`, `plate` and `hole` are used only through `hinge_deprecated`, for the latch.) `hole_type` is an ordinary cell: 0 none, 1 plain, 2 countersunk, 3 counterbored. Change it and recompute to switch the hole shape. Every hole face is grown by `tolerance` along its normal. A plate's `screws_x` × `screws_y` holes are spread evenly between its `edge_margin`s (the margin runs from the edge to the outermost screw centres); a count of 1 centres the screws in that direction.

### Hinge

`hinge` is the library's hinge: VerticalHinge3, the hinge printed and confirmed for the hybrid case (`primlib/assemblies/hybrid_case.py`), and 3b, the same hinge 13 long with 2 rings and 7.5 side plates. It prints in place, standing on end: two sides of interleaved rings on a pin, each side with a leaf to screw to a panel. The axis runs along z from 0 to `length` (40); side A's leaf runs along +x and side B's along -x, their mounting faces at +y, `pin_d` / 2 + `pin_gap` + `ring_wall` + `backset` from the axis. There are `rings` (4, at least 2) rings, `length` / `rings` apart, side A's the first and every other one, on a pin of flared slices, one per ring. `side_a` (18; 3b 7.5) is each leaf's side plate beyond its tab, and `side_b` follows it unless set shorter to clear something (the T hinge under a corner). Each leaf is cut clear of the other side's rings over half a turn, so the hinge rolls from folded flat to open flat; its square edges carry a 45° `chamfer`. The result is a compound of `{name}_side_a`, `{name}_side_b` and the pins. The hybrid case builds its hinge row from it.

### Hinge (deprecated)

> **DEPRECATED.** `hinge_deprecated` is the old ring hinge, kept only because `latch` is built on it. Don't use it for new work. It goes, with `pin`, `sleeve`, `sleeve_clearance`, `plate` and `hole`, once the latch has moved to `hinge`.

`hinge_deprecated` builds a print-in-place ring hinge along the z axis. Five main specifications set its size and movement; everything else is second-level, under Pin and rings, Tabs and pose, and Plates and screws.

- **Length** (`length`, 40): along the axis.
- **Leaf Length** (`leaf_length`, 25): the side plate. It starts on the barrel's tangent, `barrel_diam` / 2 from the axis, so a leaf ends `barrel_diam` / 2 + `leaf_length` from the axis (31.5 at the defaults).
- **Barrel Diameter** (`barrel_diam`, 13): the rings' outside diameter.
- **Pin Offsets** (`pin_offset_a`, `pin_offset_b`): the axis to each leaf's mounting face. They default to `barrel_diam` / 2, and B follows A until edited.
- **Angle Range** (`angle_min`, `angle_max`; 0 to 180): the opening between the leaves, 0 folded back to back and 180 open flat. The build stops if the range is out of order or past `angle_limit`, but nothing printed stops the hinge yet. The limit is set by thin fingers of tab at the joints, where the other side's ring tapers: 182.6° at the defaults, about 224° at offset 5.5 and 245° at offset 5, with a 13 mm barrel.

A captive column of retained pins runs through `rings` sleeves that alternate between side A and side B. Neighbouring rings are `end_gap` apart (default 0.1). `ring_ends` sets the ring ends at the joints: 1 (default) shortens each sleeve so its ends stay pointed tips, and the hinge's own ends then sit `end_gap`/2 in from 0 and `length`; 0 slices a slab out instead, leaving flat lands, with no allowance at the hinge's bottom or top. Each side has a rectangular interface tab, cut clear of the other side's rings by `roll_clearance`.

- **Plates:** `plates` = 1 ends each tab on the tangent and adds a plate (the `plate` primitive, with its screws and hole type) continuing it, flush with the mounting face. The build checks that each plate's near corner clears the other side's ring by `roll_clearance`. `plates` = 0 gives tabs only, each ending `tab_reach_*` beyond the ring's outside.
- **Pose:** `pose_a` and `pose_b` are the leaf directions as built. `pose_b` = 180° is open flat, and an opening of X is `pose_b` = 360° − X.
- **Result:** a compound of three separate solids: side A, side B and the pins.

### Latch

> **TODO, NEXT UPDATE: MOVE THE LATCH TO THE NEW HINGE.** The latch is built on `hinge_deprecated`, the old ring hinge. Its next update must rebuild its main and bail hinges on `hinge` (VerticalHinge3) and print-test them; then `hinge_deprecated` and the primitives only it uses can be deleted.

`latch` builds an over-centre bail latch, closed, made to print and kept plain: hinge primitives for the hinges, boxes and cylinders for everything else (and cones for the countersinks). The base and lever are blocks on `arms` + 1 main hinge sections, one at each end of the latch and one between each pair of arms, each with a base ring at both ends. The bail has `arms` straight arms, each `bar_height` thick, in the bands between the sections, where there's no pin. They pivot in the lever on a further hinge primitive, the bail hinge: 2 · `arms` + 1 rings the latch's width (lever, arm, lever, ...) round an M3 bolt as the pin (the hinge's printed pins aren't used; the rings keep a printed pin's bore, `bail_bore` at the throat, flared to pointed ring ends). Their far ends join the bail bar, a cylinder the main hinges' diameter the latch's height, reinforced by an M3 bolt along it; it drops into a half-round seat on the keeper. Each arm is the latch's depth, flush with the lever's back and front faces, a plain bar from the bail hinge axis to the bar. In each arm band the lever and base are cut right through, the lever deeper ahead of the bail hinge (as far below its axis as the arm's front corner is ahead of it, plus `slot_clr`) so the bail can swing 90° forward, so the base is a separate pad on each main hinge section; the lever's own back face tapers `lever_taper` in from just under the bail hinge to its tip. The keeper is a block in line with each main hinge section, `hinge_height` along the axes, with the arms passing between them; where its seat comes within `keeper_min_wall` (0.5) of the wall, the thin edge there is cut off. The base block and keeper are the same height, `main_gap` apart: the parting line (`parting_y`, derived) sits midway between them.  Base, lever, the main hinge pins and the bail print in place together, standing on end (the bail is loose until its hinge bolt goes in), with print supports (`{name}_print_support`, built beside the result, not in it), in every arm band, each running face to face with its interface layers `support_z_gap` (0.1) off the faces: `support_rect`s the latch's depth under and over the arm, and under the rest of the arm out to the bail bar (on the bed for the first arm, on the arm below for the others); across, they are cut `support_gap` (0.2) clear of the printed parts, with a wall a line wide closing the cut round the bail hinge ring; the keeper prints separately, each block a separate part (`{name}_keeper_0` up, compounded as `{name}_keeper`); each arm sits `arm_gap` clear of the parts below and above it, room for the supports. The base and keeper take a countersunk self-tapping screw (4g × 5/8": Ø2.9 thread, Ø5.6 head, 90°) in every main hinge section's band: a `screw_len` (16) screw, head included, into the `ply_t` (6) box wall, its tip `screw_len_tol` (0.5) short of the far side (`screw_past` moves it), with a bore the head's size in front of the head; holes and countersinks are `screw_tol` (0.3) over size, and the build prints how far the heads sit below the base and keeper fronts. The number of keeper blocks and of the supports standing on the arms below is set when the latch is built: rebuild after changing `arms`.

- **Sheet sections:** Catch (`height`; `arms`; `latch_width`, lever tip to the far side of the bail bar; `max_depth`, wall to lever front; `hinge_diam`; `hinge_spacing`, bail hinge to main hinge; `bail_length`, bail hinge to bar; `backset`; `bar_offset`; `arm_gap`; `bar_height`; `main_gap`), then Main hinges (`rings` is per hinge and must be odd), Bail (the bail hinge's ring and bore, clearances, the bolts, their head recesses and nuts), Mounting screws, and Parts. The lever length and the main hinge axis's distance from the wall follow from `latch_width` and `max_depth`; the first derived value is each main hinge section's height, `hinge_height` = (`height` − `arms` · (`bar_height` + 2 · `arm_gap`)) / (`arms` + 1). The bail hinge's rings are equal for now, so `bar_height` defaults to `height` / (2 · `arms` + 1) − 2 · `arm_gap`; the build prints the difference if it's overridden. The latch declares no checks: values aren't validated when it builds. The docs page shows the drawing straight after the parameter table.
- **Lock:** given as lengths, not angles. `backset` is how far the bail hinge lies behind the line from the main hinge axis through the bar when closed, and `bar_offset` is the bar's distance out from the main hinge axis. The over-centre angle (asin(backset / hinge_spacing)), the stretch the bail takes while the bail hinge passes centre, and the arm's lean from the wall follow, and the build prints them with recommended targets (10–20°, 0.3–0.6 mm, about 0°).
- **Bolts:** two ISO 7380 M3 button head bolts, `bolt_len` (50) under the head, one along the bail bar and one as the bail hinge's pin. Each head sits in a recess in the bottom end, `recess_h` = `bolt_head_h` + `head_gap` deep and `head_clr` over size, and its nylock in a hex pocket in the top end, `nut_clr` over size. The recess's roof is a `bridge_skin` (0.2) across the bore, printed as a bridge and pushed through by the bolt. `height` (52) is set so the tips end inside the nuts; the build prints the tips' distance below the top face (must be 0 or more) and their length in the nuts.
- **Frame:** x points out from the box wall, y up towards the lid, and z along the hinge axes. The origin is on the main hinge axis, and the wall is at x = −`pin_y` (`max_depth` − `hinge_diam` / 2).
- **Result:** a compound of base, lever, main hinge pins, the bail (arms, rings and bar), keeper, and the hardware (both bolts and their nuts).

### Rotary latch

`rotary_latch` (not yet printed) is a lid latch: a hex knob (`knob_af` across the flats) on a pin on the body reaches over the lid joint and turns over an arc of `rail15` on the lid. The knob's back carries the `rail15_housing` slot at `clearance`, revolved about the pin at `rail_r`, with a notch at 12 o'clock and a lead-in ramp each side (an eccentric copy of the slot, `pull_down` out at the notch, in to true over `ramp_a`), so it locks turned `turn` either way. The pin is as big as fits (`wall_in` of knob between bore and slot). The lid plate is built where it's mounted, `preload` above locked, so locking pulls the lid in and `pull_down` - `preload` is left for tolerance. Both plates are `plate_w` wide with four countersunk M3 each on the same lines (x = ±`screw_x`), and a one-layer `bridge` joins them for printing as one piece. The result is a compound of `{name}_base`, `_knob`, `_cap`, `_lid` and `_bridge`. The project script adds the loads, the motion checks (gap through the turn both ways, the rail dropping in, the ramps meeting a raised lid) and the print layout.

### Stencil

`stencil` (not yet printed) is a pair of text templates for a board: up to six lines of text (`lines`, and each line's `text{i}`, `font{i}`, `size{i}`, its anchor `line{i}_x`, `line{i}_y` from the text's origin `origin_x`, `origin_y`, and its justification `h{i}`, `v{i}`, all sheet cells, lengths in mm on a project's sheet) cut through a plate `length` × `width` × `thickness` that lies on the board's face, registered by fences under its edges, `clearance` off the board's edges: `fence_top`, `fence_bottom`, `fence_left` and `fence_right` switch each on (1) or off (0), so it can sit on a corner (two adjacent fences, the default bottom and left) or on one edge only (the top fence alone, for text in the middle of a large board). The origin is the template's centre on the board's face; `length` × `width` is its overall size, fences included, and the text's origin (`origin_x`, `origin_y`) is measured from that centre. The letters' centres are held by thin bridges: template A's at `bar_a1` and `bar_a2` of the capital height, template B's at `bar_b1` and `bar_b2`, so B opens what A's bridges hide. Both register on the same fences. For a router with a bearing-guided bit, `thickness` is at least the bearing's height, and a check keeps A's and B's bridges at least `bridge_w` + `bit_d` apart. Each template is the plate less the extruded text less its bridges. There is no bevel: FreeCAD's tapered extrusion, offset, fillet and chamfer all fail on text outlines. Each line is a Draft ShapeString (`Builder.shapestring`, extruded with `Builder.extrude`), live from the sheet; its font is a file path, so the font must be installed where the file is opened. The result is a compound of `{name}_a` and `{name}_b`. The project script checks what the primitive can't before it's built (the text's length inside any fences, each template in one piece, A and B together opening every letter) and reports the router's reach.

### Rails

**Width convention.** A rail's `width` is its outside width, between vertical tangents to the tip radii, what calipers read, and everything else is worked from it. **`twist_socket` and `twist_plug` keep an older convention: `mouth_d` is the mouth's sharp diameter, so check prints against it with care.** Their pages say so too.

**The dovetail path** (`primlib/paths/dovetail.py`, its page `dovetail.html`) is the rails' section declared once: `width`, `angle`, `depth`, `tip_radius`, `root_radius`, a base above the root (`base_width`, `base_height`) that closes the outline, and an optional centre groove. `Dovetail.points(grow, face)` gives the closed outline offset normal to every face, the rounds concentric: 0 for the tongue; a clearance for its slot, base and all; minus a lead-in (`face` 0) for a lead-in, its base kept. `tests/test_path.py` holds it to the outlines the rails and housings draw today; they don't draw it yet.

The library has two rails, deliberately not interchangeable: `topeak_rail` to fit a real Topeak rack, and `rail15` for the project's own sliding parts.

### Topeak rail and housing

`topeak_rail` and `topeak_rail_housing` slide on a Topeak bike rack's rails, aligned with `rail15`: the same frame, variable names (`length`, `base_depth`, `base_width`, `end_taper`, `printer_width_offset`, `clearance`, `block_width`, `block_depth`) and `base_width` -1 meaning; the rail's `printer_width_offset` defaults to 0.2, the housing's to 0. Eight fixed parameters define the shape: `width` 61.4 (what the print should measure, across the tip radii; a PETG piece modelled at 61.6 printed at 61.4 and fits a real rack, a whisker tight), `angle` 60, `depth` 6.35, `tip_radius` 0.7, `root_radius` 1, `groove_width` 19.95 (at the tip face), `groove_depth` 1.2, `groove_angle` 45. The rail has no tolerance; the housing's one `clearance` (0.30) is normal to every face. The offset moves the flanks only: the groove and guide stay at their design size. A real rack isn't made to the housing's numbers; the housing is the printed mate. Full specification: `primlib/primitives/topeak_rail_spec.html`, from `freecadcmd make_topeak_rail_spec.py`, which measures the solids and won't write the page if they disagree with the working. The rail's `screws` option (0, off, by default) cuts two rows of countersunk holes up through the tongue, heads in the tip face, `screw_y` off the centre line and spaced like `box_edge`'s rows (`drill_inset`, `nominal_spacing`, `min_spacing`), to screw it to a panel; it turns on and off live.

### 15 mm rail and housing

`rail15` and `rail15_housing` are a small sliding dovetail. Four fixed parameters define the shape (the core's `fixed` class option: read only on the sheet, listed apart in the docs): `width` 15 (between vertical tangents to the tip radii, what calipers read), `angle` 60, `tip_radius` 1, `root_radius` 0.2. The rail's variable parameters are `length` (20), `depth` (4), `base_depth` (1, must be more than 0, since the root radius needs it), `base_width` (-1, as wide as the root including its radius), `end_taper` (0, off) and `printer_width_offset` (0), and the sheet shows only those ten values. The rail has no tolerance. The housing adds `clearance` (0.20), the gap normal to every face, per side, so the slot's widest point is 15 + 2 x `clearance`, plus `block_width` and `block_depth`. Its mouth's lip has radius `root_radius` - `clearance`, so from 0.20 up it's sharp, chosen at build time; the gap stays `clearance` either way. `end_taper` on either part adds lead-ins at both ends: over the last `end_taper` of the length the rail's tapered part shrinks by it, or the slot grows by it, normal to its faces, so at 45° along x (a ruled loft through four sections; on or off is fixed at build time); the rail's support and the housing's mating face stay put. The rail's root is always z = 0 and the housing's mating face is at z = -`clearance`, so the pair mate at the same origin. `printer_width_offset` is added to the width in the model (the rail's width, the housing's slot), half to each side across y only, each part with its own value, so depth, angle and radii stay exact. All of it is dimensioned and worked through in `primlib/primitives/rail15_spec.html`, generated by `freecadcmd make_rail15_spec.py`, which measures the real solids and refuses to write the page if they disagree with the working. No screw holes yet.

### Box edge and corner

`box_edge` and `box_corner` are the printed pieces of a box made of flat panels. The section is an L: a `skin` over each panel's outside, a web `panel_gap` wide between the panels' edges, and a `bevel` across the outside corner. Frame: the inside corner at the origin, the walls towards -x and -y (and -z for the corner), the edge along +z from 0 to `length`. `box_edge`'s two screw rows follow its length: holes from `drill_inset` off one end to `drill_inset` off the other, no more than `nominal_spacing` apart, or a single middle hole when those ends are under `min_spacing` apart. `box_corner` is three of the sections swept along x, y and z, the three bevels cut across the whole with a flat facet where they meet, and `drill_rows` by `drill_rows` holes on each face.

With `glue` above 0 (default 0), the faces that hold the panels are cut back by `glue`, leaving ridges `glue_ridge` wide (default 0.6). The panels sit on the ridges, where they sit with no glue, so no other size changes, and the pockets between are the glue line. The pockets are open at their far ends so glue and air can get out, with 45 degree sides so they print in any direction. Setting `glue` back to 0 restores the plain shape, live.

`box_edge` only: `relief` (default 0) cuts the -x wall's outside face back across the whole section, for something to pass beneath it, with the small chamfers carried round the new face by flat cuts (`Builder.beyond`), so it works on a wall too thin for the inset end sections. `holes_x` and `holes_y` (1 or 0) turn either screw row off, for a wall left too thin for the countersinks. All three switch live. The hybrid case's notched rail pieces use them.

The small `chamfer` on every straight outward edge is part of the shape (a ruled loft through inset sections, or planes cut with `Builder.beyond`), not a feature picked from edges, so it survives any change of size. A `Part::Chamfer` stores edge numbers and can break for good when a part moves or resizes.

### Support

`support` is a print support you place yourself: a wall `length` (x) by `width` (y) by `thickness` (z), corner at the origin, pierced by a row of diamond holes. It stands on the bed or a lower part at z = 0 and holds up the part at z = `thickness`. Between the holes the wall is a row of hourglasses narrowing at mid-height to a pointed neck: cut through the necks to separate the parts. The sizes are in print units, from `line_w` (0.44) and `layer_h` (0.2): the neck is `neck_lines` lines wide (default 0: the hourglasses meet in lines, so the result is two solids touching only there), the holes are at least `gap_lines` lines wide at the necks (default 2; as many hourglasses as fit share `length` evenly), and the skin along the bottom and top, which ties the hourglasses into one wall and gives the part above a full face to print on, is `skin_layers` layers (default 1). The hole flanks are at 45°, and meet at the neck, so a hole is a square diamond, as tall as its gap; the top skin takes whatever height is left, so the wall is exactly `thickness` tall. The thinnest support is a hole and both skins, `min_thickness`: about 1.28 mm at the defaults (2-line gaps); thinner is refused. Move it into place with its `Placement`, and fuse it to the parts or export it with them as one body.

`support_rect` fills a rectangle (`length` × `width` × `height`, corner at the origin) with concentric rectangular walls `wall_lines` lines wide and `gap_lines` lines (4) apart, as many rings as leave a gap across the middle, plus a middle line along the long side when the middle is wider than a gap and a line. The walls stand between two interface layers, one `layer_h` each: single-line strips across the short side at `interface_density` (0.33), laid in from both ends with a middle strip, and a line round the outside joining them. The top layer stops `interface_gap` (0.1) under the supported face, the bottom one `bottom_gap` (default `interface_gap`, 0 on the bed) above the face below. Each ring's sides are Draft arrays of stripes from each end, kept inside the triangle where that end is the nearest side, so the corners mitre and the ring count follows the sheet.

`support_half` is the same for a round part: a half cylinder of `radius` on the +y side of the x axis, concentric half-ring walls in from the rim and one along the flat side, between radial interface layers: single-line spokes from the centre, as many as make `interface_density` of the rim, joined by a line round the rim and one along the flat side. `trim` cuts it off at x = `trim` with a wall along the cut and a line in each interface layer, so the boundary stays closed (default `-radius`: the whole half). The spokes are a Draft polar array (`Builder.polar`); the number of rings is fixed when it is built.

### The Python call

```python
primlib.make("pin", doc, "Pin")                        # section "Pin" in Params
primlib.make("pin", doc, "Pin", diam=8)                # diam starts at 8
primlib.make("sleeve", doc, "Sleeve", sheet=s)         # section in sheet s instead
primlib.make("sleeve", doc, "Sleeve", prefix="")       # plain aliases height, diam, ...
primlib.make("pin", doc, "Pin", sheet=s, bind={"diam": "PinDiam"})  # use your alias
```

With `prefix=""`, parts share any alias that already exists with the same name, so a pin and a sleeve can share one `height`. `bind` points a parameter at any expression instead of adding a row for it. `s` is a spreadsheet object, for example `doc.getObjectsByLabel("d")[0]`. Each call returns the `Part::Revolution`; finish with `doc.recompute()`. The saved `.FCStd` doesn't need primlib to open: the parts are an ordinary spreadsheet, sketch and revolution.

### As a file, for other programs

A primitive can be written as a `.prim` file ([docs/FORMAT.md](docs/FORMAT.md)): its parameters, checks and operations, every size an expression over its names, so another program (view4d) can build it at any values. This needs no FreeCAD:

```sh
python3 -m primlib list                                   # what exports (all but latch and hinge_deprecated)
python3 -m primlib export hinge -o hinge.prim             # at the defaults
python3 -m primlib export pin --set height=12 -o pin.prim # at other values; the checks must pass
python3 -m primlib check pin.prim --set diam=4            # which checks fail
```

In FreeCAD, `primlib.prim.replay("pin.prim", doc, "Pin")` builds a file just as `primlib.make` builds the primitive: sheet rows, checks, objects bound to the sheet.

## Adding a primitive

1. Create `primlib/primitives/<key>.py` with one class. It declares `title`, `params`, `derived` and `checks`, and the class docstring becomes the page's description. Choose the base class by shape:
   - **`Revolved`** for a solid of revolution: give `walls(x)`, the (r, z) wall points as expressions. Examples: `pin.py`, `hole.py`.
   - **`Primitive`** for anything else: give `build(doc, name, sheet, env)`, which makes its shapes with `Builder` and returns the result (see `stencil.py`). `Machined` primitives give `body(b)` instead: a body and the tools cut from it (see `plate.py`, a box minus a grid of `Hole` tools). `Builder` makes bound boxes, cylinders, cones, sectors, polygon prisms, slots, sketch prisms (with optionally rounded vertices), ruled lofts between such polygons, revolves, arrays and grids, moves, nested primitives (`b.part`) and booleans in a line each. Build only through it: it is also how a primitive is recorded for other targets (`primlib/targets/`).
   - **`Machined`** for a body with features cut from it: give `body(b)` returning `(body, [tools])`; the result is the body minus the fused tools.

   A primitive can reuse another one's declarations, like `SleeveClearance` does with `Sleeve`, or `Plate` does with `Hole`. To build one primitive inside another, map its params to the outer primitive's names and use `b.part(Inner, suffix, bind)` (as `plate.py` does with `Hole`), with `Inner.nested(...)` and `Inner.nested_checks(...)` for its names and checks. Options for the docs page: `mates`, `fits`, `variants`, `section_y`, `front_view` and `front_dims` (see `primlib/core.py`). `summary` lists (expression, note) pairs printed to the console after a build. `intro` replaces the docstring on the page, and `views` draws the shape in third-angle projection (top, front, right side), dimensioned with labelled parameters (lengths and angles), straight after the intro, with a table of those parameters.
2. Check it records: `tools/run.sh tools/record_check.py`, then `tools/run.sh tools/replay_check.py` (its file builds the same as `make`).
3. Run `tools/run.sh make_docs.py` to write `<key>.html` and update `index.html` (not `freecadcmd make_docs.py`: that can pick up a same-named script from another installed add-on).

The primitive is discovered automatically: it appears in `primlib.available()`, `primlib.make()` and the toolbar.

Keep primitives general. Code specific to one project (assemblies, a particular hinge) belongs in that project and builds on primlib.
