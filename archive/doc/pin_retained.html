Retained pin

The retained pin is a cylindrical shaft with a splayed flare (cone) at each end that traps a mating collar axially. Once the collar is snapped over the pin the flare prevents it sliding off — hence retained. The pin is a solid of revolution, so an elevation and a plan describe it fully. These are first-angle projections; the flare cone angle is the real parameter angle (p_ang).

This page is the single source of truth for the retained pin. The part lives in the parts library fc_lib as the self-contained module pin_retained.py; other notes point here rather than duplicate it.

Module

The part is built by pin_retained() in fc_lib/pin_retained.py, a self-contained FreeCAD module with no dependencies beyond the FreeCAD core. Two signatures: the first is the base pin; the second adds the real flare angle p_ang (the module’s angle parameter) and an optional clearance (the lowest-priority parameter, listed last). 

def pin_retained(doc, name, height, diam, diam_end):
    """Retained pin: a shaft `diam` with a 45° flare `diam_end` at
    each end, `height` tall (z = 0 .. height)."""


def pin_retained(doc, name, height, diam, diam_end,
                 angle=45.0, clearance=0.0):
    """`angle` is the flare flank angle (p_ang, degrees). `clearance`
    (mm, optional) pushes every face out along its own outward normal,
    giving the overdimensioned envelope the pin must clear in a bore."""

Typical use from a script or the FreeCAD Python console: 

import sys
sys.path.insert(0, "<path to>/fc_lib")
import FreeCAD as App
from pin_retained import pin_retained

doc = App.newDocument()
pin = pin_retained(doc, "Pin", height=10.0, diam=6.0, diam_end=10.0)
doc.recompute()

The module also offers a solid-of-revolution route through profile_points(), profile_sketch() and pin_retained_revolved(), which builds the pin as a sketched meridian profile revolved about the z axis — see Method 3 under Construction.

Run the module directly (freecadcmd pin_retained.py) to build an inspection document: a solid block spanning x = ±3·rd and z = ±2·h, but only on the +y side (y = 0 … 3·rd), hollowed by the clearance envelope with the complete nominal pin in the cavity. The block’s y = 0 face reads as a section of the clearance pin around the main pin. The envelope is built from z = 0 like any pin, so it is dropped by c before the cut to centre it on the nominal pin.

Construction

The pin is a solid of revolution, and there are two equivalent ways to build it. The model uses the first (tapered frustums); the second (complete cones) gives the identical solid and is often easier to reason about.

Method 1 — tapered frustums (as modelled)

The union of three coaxial solids. Where they meet there is a small overlap, but that is irrelevant in a union, so the primitives need not abut exactly.

  1. Bottom cone (frustum) — R1 = rd/2 at z = 0, tapering to R2 = pd/2 at z = c.
  2. Shaft cylinder — radius pd/2, spanning z = c to z = h − c.
  3. Top cone (frustum) — R1 = pd/2 at z = h − c, opening to R2 = rd/2 at z = h.

In the model (pin_retained() in pin_retained.py) these are a Part::Cone, a Part::Cylinder and a second Part::Cone, combined with Part::MultiFuse. The lowest boundary sits at z = 0 and the highest at z = h.

Method 2 — complete cones

The same solid built from two complete (sharp) cones whose apexes lie on the axis, plus one full-height shaft cylinder. Each complete cone runs unbroken from an end face to its own apex; past the cone/cylinder junction its tip is narrower than the shaft and is simply absorbed by the union.

  1. Complete bottom cone — R1 = rd/2 at z = 0, apex (R2 = 0) at z = ca.
  2. Shaft cylinder — radius pd/2, full height, z = 0 to z = h.
  3. Complete top cone — apex (R1 = 0) at z = h − ca, R2 = rd/2 at z = h.

Because the shaft spans the full height and each cone tip is narrower than it, the union repeats Method 1’s profile exactly: the flank from rd/2 down to pd/2 over z = 0..c, the straight shaft in the middle, and the mirrored top flank. The two methods differ only in where the primitives are trimmed — by an explicit frustum height c in Method 1, or by the union itself in Method 2.

p_ang (the module’s angle parameter) is the real parameter: every cone dimension and every flank position in the drawings is derived from it. Changing p_ang moves the flanks, the cone/cylinder junction edges, the completed-cone apexes and the cone-height dimension together.

The flank of each end, extended inward, reaches the axis at that end’s own apex — the bottom apex at z = ca, the top apex at z = h − ca. They coincide only when h = 2·ca (true for the h = 10 mm default, not for the 20 mm sample drawn here).

Valid range: 0 < p_ang < 90 (the flank must slope), rd > pd (the cone height must be positive) and h > 2·c (the shaft length must be positive). Outside that range pin_retained() reports an error and builds nothing.

Method 3 — revolve of the sketch profile

The pin is already a solid of revolution, so it can be built directly as one: draw its meridian sketch in the XZ half-plane and revolve it 360° about the z axis. The module exposes this route as three functions: 

profile_points(height, diam, diam_end, angle=45.0, clearance=0.0)
    -> the six profile vertices P0..P5 as App.Vector (x, 0, z)

profile_sketch(doc, name, height, diam, diam_end,
               angle=45.0, clearance=0.0)
    -> the profile as a Sketcher sketch in the XZ plane

pin_retained_revolved(doc, name, height, diam, diam_end,
                      angle=45.0, clearance=0.0)
    -> the same pin as a Part::Revolution about the z axis

The profile is a closed six-point polyline; the closing segment lies on the axis, so the revolved solid is closed. Vertices are (x, y, z) with y = 0 throughout: 

P0 = (0,      0, 0)       axis, bottom
P1 = (rd'/2,  0, 0)       bottom end face -> flare rim
P2 = (pd'/2,  0, c')      flare flank -> shaft
P3 = (pd'/2,  0, h'-c')   shaft -> top flare
P4 = (rd'/2,  0, h')      flare flank -> top rim
P5 = (0,      0, h')      top end face -> axis

with the clearance-grown values (h' = h + 2c, pd' = pd + 2c, rd' = rd + 2c / tan(p_ang/2), c' = (rd'/2 − pd'/2)·tan(p_ang); primes drop when c = 0). The result is identical to Methods 1 and 2 — same volume, same bounding box — and updates by editing the sketch in the GUI.

Primitives used by pin_retained()

The function builds the pin from three Part primitives united by a fourth object. The names below use name for the argument passed to pin_retained(); the three construction solids are hidden once the union is made.

objecttypekey propertiesrole
{name}_bottom Part::Cone Radius1 = rd/2, Radius2 = pd/2, Height = c, base (0, 0, 0) bottom flare (frustum)
{name}_shaft Part::Cylinder Radius = pd/2, Height = ls = h − 2c, base (0, 0, c) straight shaft
{name}_top Part::Cone Radius1 = pd/2, Radius2 = rd/2, Height = c, base (0, 0, c + ls) top flare (frustum)
{name} Part::MultiFuse Shapes = [shaft, bottom, top] the union — the finished pin

So the whole part needs only two primitive kinds — a cone (Part::Cone, which is a frustum whenever both radii are non-zero) and a cylinder (Part::Cylinder) — plus a single boolean union (Part::MultiFuse). Method 2 above is the same three primitives with Radius2 = 0 (a complete cone) and a full-height shaft.

pin_retained() simply calls doc.addObject() directly; the module has no dependencies beyond the FreeCAD core, so it can be dropped into any project that needs the part.

Views

First-angle projection, delivered as two separate drawings: a front view (elevation, perpendicular to the axis) and a top view (plan, looking down the pin axis).

Reading the views

  • Solid outline — visible edges.
  • Solid horizontal lines in the front view — the cone/cylinder junction circles (a true first-angle view, not a section).
  • Dashed — hidden edges (the shaft circle inside the flare in the top view).
  • Dotted (ref) — construction/completion lines: the flanks extended to each cone’s own apex, and the shaft cylinder completed over the full pin height (its wall is buried inside the wider end cones there). Dotted lines also carry every dimension.
  • Each complete cone reaches the axis at its own apex — bottom at z = ca, top at z = h − ca — which coincide only when h = 2·ca.

Retained pin — clearance-included version

This page repeats both views for an overdimensioned pin. Starting from the nominal geometry, every surface is pushed out along its own outward normal by a clearance c = 0.10 mm; where two offset faces meet — the end rims — they are extended to a sharp corner. The result is the nominal-plus-clearance envelope: the volume the pin must be clear of to ride in a bore with that clearance.

nominal pin  ·  clearance envelope (+c normal to every face)

The module builds exactly this envelope in one call: the clearance parameter grows the pin to h′ = h + 2c, pd′ = pd + 2c and rd′ = rd + 2c·cot(p_ang/2), keeping the same flank angle p_ang.
